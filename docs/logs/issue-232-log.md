Issue: #232 クラウド → マシン → 作業用セッションの 3 層の運用と、メッセージの向きを docs に書く
実装日: 2026-11-28
変更ファイル:
- docs/management-session-policy.md（「10. クラウド → マシン → 作業用セッションの 3 層で進める」を追加）
- CLAUDE.md（「管理用セッション」に要点とスキル名を追加）
- .claude/skills/dispatch-machines/SKILL.md（新規。クラウドの管理用セッション用）
- unity/.claude/skills/run-worker/SKILL.md（新規。各マシンの管理用セッション用）

実装方針:
- 構成は「クラウドの管理用セッション → 各マシンの管理用セッション → 各マシンの作業用セッション」を基本にし、各層の役割とメッセージの向きを表にした
- マシン → クラウドは `send_message` を使わず、マシンの管理用セッションが最後の返答に報告を書き、クラウドが `get_session` / `list_events` で読みに行く
- 最初の流れ（Issue の状況と `docs/issue-order.md` を見て各マシンに割り振る）がぶれないよう、スキルを 2 つにした。`/dispatch-machines`（割り振りと指示、`status` で状況の確認）と `/run-worker <番号>`（作業用セッションの作成と報告）
- クラウドのセッションはリポジトリのルートで起動し、`unity/.claude/skills/` を読まないため、クラウド用のスキルはルートの `.claude/skills/` に置いた

詰まった点・解決策:
- クラウドのセッションからマシンのセッションへの `send_message` は、初回に `elevated_session_untrusted_device` で拒否された。`confirm_repository_trust` で人間が許可すると送れるようになったが、許可したクラウドのセッションは信頼済みの端末専用になり、元に戻せない
- 許可した後は、マシンのセッションからクラウドのセッションへの `send_message` が同じエラーで拒否された。マシンは報告を返答に書き、クラウドが読みに行く運用にした
- 同じマシンの中（マシンの管理用セッションと作業用セッションの間）の `send_message` は問題なく届く

残課題・関連Issue:
- スキルはこのときの手順をもとに書いたもので、スキル自体での実行はまだ試していない。次の割り振りで `/dispatch-machines` を使って確かめる
- 各マシンの管理用セッションは、`/run-worker` を使う前に `git pull` が必要
